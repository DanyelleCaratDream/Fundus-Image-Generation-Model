## 二、病灶加权的真实情况（逐条回答你的 5 个问题）

**先说结论：我们此前把它称为"病灶加权（lesion weighting）"是不准确的。代码实际只对「渗出」加权；出血检测被明确放弃。以下是自查后的如实说明。**

### Q1 权重图怎么得到的？

纯色彩/形态启发式（无像素级标注）：

1. **渗出检测**：归一化 RGB 下 `r>0.55 & g>0.38 & b<0.45 & (r−b)>0.15`（亮金色斑）；
2. **连通块过滤**：面积 20–600 px、实心度（contour area / convex hull area）≥ 0.5，滤掉细长噪声与大块；
3. **软边**：高斯模糊 σ=2 → 7×7 膨胀 → 再模糊 σ=3，让加权覆盖病灶周边；
4. **逐图 max-norm**：每张图最亮的病灶像素归一到 1.0；
5. **覆盖率上限**：若 `(soft>0.3)` 的像素超过 15%，判为误检（大面积偏色），整图权重清零。

### Q2 出血和渗出如何区分？

**没有区分——出血检测根本没有实现。** 代码注释原文（`make_lesion_weights.py:27`）：

> `# 只做渗出（金色亮斑）：实测比出血启发式可靠得多；出血/血管难区分，放弃`

docstring 里曾写的"出血：暗红（R−G 大、G 低、亮度低）"是**未实现的旧描述**，我们已更正 docstring。因此：
- 渗出区域：权重 1+λ；
- 出血区域：与普通背景相同，权重 1.0（**未加权**）；
- 视盘排除：也未实现（只有"面积>600 的大块直接丢弃"，不是视盘专用逻辑）。

### Q3 血管为什么降权？

**血管没有降权。** 血管 mask（来自条件的血管骨架）只用于**从渗出 mask 里减除**（阈值 >60、膨胀 5px），因为"血管边缘是最主要的渗出假阳性来源"（`make_lesion_weights.py:30`）。减除后血管像素的权重 = 1.0，与其他背景像素相同，**不是低于 1.0 的降权**。我们报告中"血管区域降权"的表述是错误的。

### Q4 加权 L1 如何计算？

CFM 分支（`train.py:1251–1254`）：

```
w   = 1.0 + λ · weight_map      # 逐像素；weight_map ∈ [0,1]
loss = ( |v_pred − v_target| · w ).sum() / w.sum()
```

- 作用在**速度预测的 L1** 上（CFM 目标 `v = x1 − x0`），不是图像空间 L1；
- 背景权重恒为 1.0，渗出中心最高 1+λ；
- **λ = 8.0**（写在该实验 config `cfm256_lesion.json:12`，不是代码默认值 5.0）；
- 分母 `w.sum()` 做权重归一化，保持 loss 尺度与普通 L1 可比。

### Q5 权重有没有归一化？

有三层，但**没有 sum-to-one、没有全局 max-clamp**：
1. 逐图 max-norm（最亮病灶 = 1.0）；
2. 覆盖率 >15% 整图清零（误检保护）；
3. loss 按 `w.sum()` 归一。

### 由此产生的更正

| 原表述 | 更正为 |
|:--|:--|
| "病灶感知加权 / lesion-aware weighting" | **渗出区域加权（exudate-weighted）** |
| "出血保留率 +24% 归因于加权" | 出血**未被加权**；+24% 是附带现象，不作归因 |
| "血管区域降权" | 血管仅用于减除渗出假阳性，权重不变 |
| "排除视盘" | 未实现；仅面积上限 |

上述更正已同步到：`paper/ch5-results.md` 5.8.3、`paper/outline.md`、`EXPERIMENTS.md` 执行记录 21、`make_lesion_weights.py` docstring。

## 四、我们自查发现的 5 个问题（主动披露）

### ① HR/DR 术语污染（**已确认是真错误**）

项目研究对象是**高血压视网膜病变（Hypertensive Retinopathy, HR）**，采用 Keith-Wagener-Barker 分级（KW I–IV，severe = KW-IV）。这与你报告里看到的"DR 四级分级"不一致——**是我们写错了**。全仓库约 24 处 CLASS A 错误（把本项目的疾病写成 DR），最严重的是 `research-report/_build_report_ml.py:143`：

> "本报告用 330 张严重糖尿病视网膜病变（DR，Keith-Wagener IV 级）眼底彩照"

（KW-IV 是高血压分级，与糖尿病无关）。DL 报告正文 1 处（第 640 行）、paper ch1/outline、docs/ 5 处、classify_project/ 4 处也会一并修改。3 处 SD 文本 prompt 里的 "diabetic retinopathy" 是**历史事实**（B1 线借用了 KylianSu 的 DR LoRA），保留原文、加注说明，不改。

### ② FID 参照集 = 生成器训练集子集（你提的"72 张参照"问题，比想象更严重）

- `eval_data/real_severe_train`（72 张）与生成器训练池（193 张）做感知哈希比对：**63/72（88%）内容相同，其中 61 张像素级完全相同** → **FID 衡量的是"拟合训练分布"，不是泛化**；
- 好消息：生成器训练池**不含** val/test severe（文件交集为空，此前已清理 16 张跨 split 泄漏文件）——你担心的"训练用了测试图"没有发生；
- 但教师官方 split 本身有跨 split 同图（如 `80024(val)≡80052(train)`、`80029(val)≡80038(train)`、`80028(test)≡80055(train)`，均 MSE=0），全树 113 对跨 split 相似 → 下游分类基线 QWK 0.747 含乐观偏差，需转告老师并考虑按眼/序列重划分。

### ③ 指标实现的三个缺陷（你指出的方向问题，部分比"写反了"更严重）

- **MS-SSIM**：代码方向一致（越低=多样性越好）；但报告第 6 章两处表格写成"越接近 1 越好"（与第 2 章和代码矛盾），且该标签会影响 D3 vs CFM 的排名——这是报告文本 bug，需改；
- **KID**：代码里声明的子集自助抽样（`num_subsets=100, subset_size=100`）是**死代码**，实际只算了一次全矩阵（含对角、有偏）估计，且**没有任何方差输出** → 72 real + 60 fake 下的 FID/KID 差异（如 121.84→115.22）**统计上不可靠**，不能作为"渗出加权改善了分布"的证据。**（该缺陷已于 2026-11-06 修正为无偏子集自助并输出 std；旧数字待重算。）**
- **C2ST**：方向（越低越好、理想 0.5）正确，但所有方法 AUC 在 **0.836–0.944**，距 0.5 仍有 0.34–0.44——**全部仍可被轻易判别**。"CFM@256 真实性领先"只能靠不稳定 FID/KID + 专家目检支撑，不能靠 C2ST。

### ④ 病灶保留率是未验证的亮度计数（你担心的"是否真识别到病灶"成立）

实现是颜色阈值计数（出血：`R<0.42 且 R−G>0.04 且 R−B>0.04`；渗出：`min(RGB)>0.42 且 mean>0.48`），**没有对照任何像素级标注验证**。反例：DCGAN 的全白图渗出存在率 = 1.0、保留率 = 40×；VAE 暗糊图出血存在率 = 0.91——该指标实际在测整体亮度。且真实渗出中位仅 0.067% 像素，阈值被压到 0.034%，**任何带视盘的图都能过**；保留率 >1 是除以极小分母的伪影。这个指标需要重做（或降级为"亮/暗像素占比"并明确其局限）。

### ⑤ 补充：即使最佳模型也需手工筛图

film_l1lpips 的干净样本率约 25–30%（见论文 5.5）；CFM@256 这批 60 张里，按上述启发式有 **8 张渗出分数为 0（约 13%）**（见 `02_lesion_strength_sheet.png` 上排）。这支持你的判断：整体像 ≠ 病灶对；也说明交付筛选 76 张需从 300+ 张中挑。

### ⑥ 加权损失归一化 3× 尺度（2026-11-06 新增，代码已修复）

- 数据集返回权重 `[1,H,W]`（单通道灰度 /255，范围 [0,1]），batch 后 `[B,1,H,W]`；
  速度预测 `predicted` 与目标 `v_target` 为 `[B,3,H,W]`。
- 旧写法 `loss = (|pred-v| * w).sum() / w.sum()`：分子按 3 通道累加，分母只计 1 份 → **恒为预期加权均值的 3 倍**；
  λ=0 时也等于 `3 × F.l1_loss`（单测已复现 3.000000）。
- 训练日志实证：cfm256 末段 0.1083 vs cfm256_lesion 0.3312 = **3.057×**。
- 次生影响：L1 主损失相对 LPIPS(0.1)/颜色(0.01) 正则的强度被放大 3 倍，实际训练平衡与配置意图不符。
- 另：加权分支无条件用 `torch.abs`，会静默覆盖 `--loss_type mse`（历史配置本就是 L1，无实际数值差异）。
- **修复**：`w = (1+λ·lw).expand_as(predicted)`，分子/分母同形状；λ=0 严格等于 `F.l1_loss`；
  同时尊重 mse/l1。7 项单测全过（`code/test_weighting.py`）。

### ⑦ 增强不同步：图像翻转/旋转，权重图与血管 mask 不跟随（2026-11-06 新增，代码已修复）

- 图像变换含 `RandomHorizontalFlip(p=0.5)` + `RandomRotation(±15°)`；权重图在变换之后从原文件读取，
  **不跟随**；`cond_transform` 在 train.py 构造但**从未传入 Dataset**，cond 也 raw 读取。
- 后果：约 100% 样本存在旋转错位（角度连续，恰为 0 的概率为零），约 50% 额外水平镜像；
  半径 100 px 处 15° 旋转位移约 26 px。**渗出加权实际施加在错位区域**——诊断中翻转后
  权重与渗出区域重叠从 **0.551 → 0.000**。
- 波及范围：D3、CFM@128/256、10-26 全部消融、渗出加权（均使用 cond）。
- **修复**：每个样本只采样一次 flip/angle，用同一组参数作用于图像、cond、权重图；
  删除死代码 `cond_transform`；默认路径行为不变（`augment=False`）。单测：同步增强 IoU 0.81，仅翻转图像时 0.00。
- **影响结论**：cfm256_lesion 的 +36%/+24% 不再作为方法证据；其余条件模型的"条件跟随"类结论需加限制，
  图像质量类指标（FID/目检）仍可参考。

## 八、当前研究状态与结论边界（按你的建议加入）

> 截至 2026 年 11 月 6 日，我们已经完成了从多种生成模型探索到 CFM 生成方案的初步实验，并尝试通过渗出区域加权改善生成图像中的局部特征保留情况。
>
> 目前的实验结果表明，时间语义对齐、文本条件和渗出区域加权等设计具有进一步研究价值，但受限于训练数据规模、评价参照集与训练数据的重叠、部分指标尚未经过医学标注验证、加权损失实现缺陷与增强错位、以及独立训练种子不足，现阶段尚不能据此得出模型具有稳定医学结构保真能力或优于其他方法的结论。
>
> 下一阶段将优先完成代码与评价指标自查，修复数据划分问题，补充受控消融和重复实验，并通过医生盲评验证生成图像的医学合理性。下游分类实验将在严格的数据隔离条件下开展。
>
> 我们希望在现有实验基础上，进一步明确方法的有效范围及其局限，而不是将尚未验证的现象作为方法贡献。

**具体边界**：单中心、小样本（193 张训练图）；72 张 FID 参照与训练池同源（63/72 内容相同、61 张像素级一致），
FID 衡量训练分布拟合而非留出泛化；KID 已改无偏子集自助，方差大，不作显著性声明；病灶指标为颜色阈值代理，
未对照像素级标注；尚无医生盲评（97/100 是作者自检）；全部训练为单 seed 42；
cfm256_lesion 受两个缺陷影响，仅作探索性记录。不声称临床可用性、泛化能力或方法优越性的因果结论。
