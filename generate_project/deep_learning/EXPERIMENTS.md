## DL-EX-015：severe 76 张 @256 从零训（❌ 失败）

- **日期**：2026-10-15 夜
- **动机**：老师的数据集 `HRSG_4_758` 里 severe 类只有 76 张唯一底图（另 76 张是数据集自带的垂直翻转副本）。计划用生成模型产出新的 severe 图替换那些翻转副本。先试"在老师的图上学一个生成器"。
- **数据**：`fundus/severe_train_sq256`（76 张，居中裁正方形后缩到 256）
  - ⚠️ 只用 train，**不碰 val/test**——因为扩充后的数据集要训分类器，碰 test 会造成泄漏
- **条件**：`conditions_severe_train`（76 张血管 mask，由 `prep_conditions.py` 生成）
- **关键超参**：`img_size=256, base_dim=64, batch_size=2, epochs=800, lr=1e-4, L1+LPIPS(0.1), ema_decay=0.9999, cool_sleep=-0.5`

```bash
python train.py --dataset_path ../../../../fundus/severe_train_sq256 \
    --cond_path ./conditions_severe_train --output_dir ./results_severe256 \
    --img_size 256 --base_dim 64 --batch_size 2 --dim_mults 1 2 3 4 --attn_layers 2 \
    --epochs 800 --use_lpips --lpips_weight 0.1 --color_weight 0.01 \
    --ema_decay 0.9999 --use_scale_shift_norm --cool_sleep -0.5 --num_workers 0
```

- **产物**：`results_severe256/`（16 个检查点 + final_model.pth）
- **结果**：
  - loss：0.742 → **0.05~0.07 收敛**（与 DL-EX-014 的 0.052 同量级）
  - **生成结果：彩色斑点噪声 / 紫蓝色糊块，从 epoch 50 到 800 全程如此**
- **失败分析**（排查过程值得记录）：

  | 检验 | 结果 | 判定 |
  |:--|:--|:--|
  | 训练 loss 收敛 | 0.74→0.05 | ✅ 正常 |
  | 预测噪声与真值相关性 | +0.995~1.000 | ✅ 优秀 |
  | 噪声预测 L1（全零基线 0.80） | **0.026** | ✅ 优于对照的 0.041 |
  | 重建（真实图加噪到 t=500 再去噪） | MSE 46.3（对照 39.7） | ✅ 正常 |
  | **从纯噪声生成（t=999 起步）** | ❌ 糊块 | ❌ **失败** |
  | **对照：同代码跑 A 域模型（330张@128）** | ✅ 正常眼底图 | — |

  **根因**：模型只学会了「局部去噪」，没学会「整体数据分布」。这是**数据量不足**的典型特征，不是代码问题。

- **规模对比**：

  | | 成功案例 DL-EX-014 | 本次 |
  |:--|:--|:--|
  | 训练图数 | 330 | **76**（0.23×） |
  | 分辨率 | 128×128 | **256×256**（4× 像素） |
  | 模型宽度 | base_dim=128（86.9M） | **base_dim=64（21.8M）** |
  | → 建模难度 | — | **约 17 倍，且容量减半** |

- **结论**：**76 张 @256 + base_dim=64 训不出可用模型。** 直接拿老师数据从零训这条路走不通。
- **下一步**：拆解成三个变量逐一验证（→ DL-EX-016/017/018）。

> **排查中的两个教训**：
> 1. **不能只看统计量判断生成质量**——失败样本的均值/标准差（86.7/48.6）与正常图（80/50）很接近，但图像是糊块。**必须看图。**
> 2. 曾误判 EMA 权重是主因（中途发现 `ema_state_dict` 少一个键 `time_embedding.timembedding.0.weight`，因为该 `nn.Embedding` 的 `requires_grad=False` 被 EMA 类跳过）。实际 `generate.py` 会先加载原始权重再叠加 EMA，该缺失无害。**不是根因。**

## DL-EX-016 / 017 / 018：变量拆解（2026-10-16）

**设计**：把失败的配置拆成单变量，逐一验证。

| 编号 | 相对 DL-EX-015 改什么 | 验证什么 |
|:--|:--|:--|
| **DL-EX-016（A）** | 分辨率 256 → **128** | 分辨率是不是主因？ |
| **DL-EX-017（C）** | base_dim 64 → **128**（保持 256） | 容量是不是主因？ |
| **DL-EX-018（B）** | 从零训 → **微调 A 域模型** | 迁移学习能不能救？ |

**运行方式**：`bash run_experiments_ABC.sh`（三实验串行，自动等 GPU）

**评估方式**：每个实验跑完用 `generate.py --use_raw` 出 4 张图。
> ⚠️ **为什么用 `--use_raw`**：EMA 权重在续训过的 checkpoint 上可能退化（DL-EX-015 排查中发现）。
> `--use_raw` 是 2026-10-16 新加的开关，强制走原始权重。

**待填**（跑完后补）：

### DL-EX-016（A：128px）结果 —— ❌ 失败

- **执行**：2026-10-16 13:39 起，跑到 **336/800 轮** 时人工中止（用户看过 epoch 300 的预览图后判定无望）
- **超参**：`img_size=128, base_dim=64, batch=2, L1+LPIPS, cool_sleep=-0.5`（相对 DL-EX-015 **只改了分辨率**）
- **产物**：`results_A_severe128_scratch/`（6 个检查点：50~300）
- **result**：
  - loss：0.740 → 0.08（收敛正常）
  - **生成质量：epoch 75 / 150 / 225 / 300 的预览图全部是灰色噪声**，只有 epoch 25 还有一点色彩结构
- **结论**：**分辨率不是主因。** 128px 与 256px 同样失败。

> **由此排除的假说**：分辨率过高（256 vs 128）。
> **由此增强的假说**：数据量不足（76 张）。**理由**：两个失败实验的 loss 都正常收敛到 0.05~0.08
> （与成功案例 DL-EX-014 的 0.052 同量级）——**模型能拟合训练目标但无法生成**，
> 这个组合指向"没形成数据分布的先验"，而不是"容量不够拟合"。若真是容量不足，loss 会卡在高位。

### DL-EX-017（C：256px, base_dim=128）结果 —— ❌ 中止（未完成）

- **实际情况**：原实验链 A→C→B 中，A 被人工中止后脚本自动进入 C；跑到 epoch 22 时随用户决定（改跑 B）被终止。
- **product**：`results_C_severe256_bd128/`（仅 22 轮，无检查点——第一次存档在第 50 轮）
- **⚠️ 实验设计缺陷（重要）**：C 与 DL-EX-015 相比**同时变了「分辨率」和「模型容量」两个变量**，因此**即使跑完也不能干净地归因**。
  若要验证"容量"假说，正确做法是 **128px + base_dim=128**（与 DL-EX-016 只差容量这一个变量）。
- **结论**：未完成，未取得有效结论。**该项实验暂时搁置**——理由见下。

> **为什么搁置**：DL-EX-015/016 的 loss 都正常收敛到 0.05~0.08（与成功案例 DL-EX-014 的 0.052 同量级）。
> 若真是容量不足，loss 会卡在高位。**"能拟合训练目标、但生成不出"这个组合指向数据量不足，而不是容量不足。**
> 因此优先验证更可能的假说（DL-EX-018 微调），暂不花 2~6 小时跑容量对照。

### DL-EX-018（B：微调）结果 —— ⚠️ 部分成功

- **执行**：2026-10-16，从 A 域最佳模型（epoch 779）续训到 **epoch 1100**（+321 轮，含 cool_sleep）
- **超参**：`img_size=128, base_dim=128, batch=2, L1+LPIPS, cool_sleep=-0.5`，数据 76 张 severe train
- **产物**：`results_B_severe128_finetune/`（checkpoint 950~1100 + final_model.pth）
- **result**：
  - loss 轨迹：0.071（起点，epoch 781）→ 0.070~0.075 波动（epoch 1100）——**起点即已收敛，小数据上继续训 loss 几乎不动**
  - **生成质量（`--use_raw` 原始权重，DDIM 100 步，8 张）**：
    - ✅ 可用：2/8（0000、0002：有真实视盘/血管/病灶点结构，0002 最像 severe）
    - ⚠️ 勉强：2/8（0001 颗粒噪明显、0005 褪色发糊）
    - ❌ 失败：4/8（彩色/灰色噪声糊团）
    - 预览图（EMA 权重）同样一半格子有结构一半是噪声
- **结论**：**微调保留了大部分生成能力（对比从零训的 0/8），干净样本率 ~25% 与 DL-EX-014 的实测常态（25-30%）持平**。
  但有两点硬伤：① 失败样本表现为整体噪声崩坏（比 DL-EX-014 的"图不干净"更严重）；② 输出是 **128px**，
  与 Phase D 的 256 标准不符，放大到 256 会损失质量。
- **下一步**：微调路线"能用但要大量人工挑选"。是否作为正式生成路线，等 D1/D2（数据量假说）结果一起决定。

## 附：本次排查中确认的事实（供组员参考）

1. **`train.py` 的噪声预测主损失已有 `--loss_type {l1,mse}` 开关**（2026-10-16 加入，默认 l1，自动记入 config.json）。
   此前 L1 写死、文件头注释还停留在 MSE，论文核心消融「MSE 溶解病灶 vs L1 修复」的 MSE 臂无法复现——**现已可复现**：
   `--loss_type mse`（LPIPS/颜色正则按需用现有开关加减）。历史教训：写死的关键超参 + 过时注释，排查 DL-EX-015 时绕了弯。

2. **`train.py --help` 曾直接崩溃**（argparse 把 help 字符串里的 `99.99%` 当格式符），已在 2026-10-15 修复（转义为 `%%`）。

3. **`train.py` 新增 `--cool_sleep`**（2026-10-15）：每个 epoch 后休眠，负数表示按 epoch 时长比例自适应。
   用于笔记本 GPU 降温（实测温度 76°C → 65°C，代价是训练时间 ×1.5）。

4. **`generate.py` 新增 `--use_raw`**（2026-10-16）：强制用原始权重而非 EMA 权重。

5. **训练前务必把数据预缩到目标分辨率**。直接读原始大图（中位边长 1900、单张最大 7.7 MB）会让每个 epoch 重新解码数百 MB，**实测慢 15 倍**（37 分钟 → 2.3 分钟/种子）。

6. **笔记本 GPU 会热降频**：长时间满载会触发 `SW Thermal Slowdown`，训练速度明显下降。
   跑长任务前先 `nvidia-smi` 看温度和降频状态。
