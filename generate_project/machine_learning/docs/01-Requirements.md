# 需求规格：传统 ML 生成眼底图

> 更新日期：2026-08-03 ｜ 对应根目录 `docs/01-Project-Overview.md` 的子集（仅传统 ML 方向）

---

## 1. 项目目标（一句话）

用 330 张严重症状眼底彩照（DR 分级 KW IV 级），通过**传统机器学习/经典 CV 方法**生成"相似但不相同"的新眼底图，用于**扩充 DR 分级分类器训练集**。

## 2. 核心约束（必须满足）

| # | 约束 | 说明 | 违反后果 |
|:--|:--|:--|:--|
| R1 | **只做传统 ML** | 本目录不用深度学习生成。已做的深度方法见 `generate_project/deep_learning/`；预训练见 `generate_project/pretrained/` | 方向混淆，与老师 Bug 2 分工不清 |
| R2 | **相似但不相同** | 生成图要"像真实重度眼底图"，但**不能复制训练图**（整图或局部） | 扩充训练集无意义；评估"记忆检测"维度直接暴露 |
| R3 | **保留病灶** | 出血/渗出/微动脉瘤等 KW IV 病灶必须可辨认（这是医生诊断依据） | 下游分类器学不到病灶特征 |
| R4 | **对齐评估口径** | 128×128 RGB，输出 `eval_data/{model}/singles/sample_XXXX.png`，各方法 300 张 | 评估体系（metrics/score/plot）无法复用 |
| R5 | **可复现** | 固定随机种子（默认 42）、记录超参数、输出 config 说明 | 实验不可复现，报告无法交代 |
| R6 | **规模化友好** | 新方法只需在管线某层插入，不重写全套 | 规模化扩展成本高 |
| R7 | **小样本边界意识** | 330 张处于"增广/生成有效性边界"，不假定方法必然有效，需实证 | 结论过度乐观 |

## 3. 功能需求

### F1 生成 300 张评估图
每个方法产出与真实集同口径的 300 张图，命名 `sample_0000.png` 起。

### F2 复制检测
生成后必须能跑"复制检测三件套"（NN-SSIM/LPIPS 距离分布、全图复制率、补丁重复率），验证"相似但不相同"。

### F3 评估接入
产出 JSON 进 `eval_data/` 后，重跑 `score_scheme.py --scorecard` 和 `plot_metrics.py` 即得综合分 + 图表（复用，不新建）。

### F4 参数可控
关键超参数（主成分数 k、GMM 分量 K、补丁大小等）通过 CLI 暴露，便于网格搜索与复现。

## 4. 非功能需求

| # | 需求 | 说明 |
|:--|:--|:--|
| N1 | 可复现 | seed 固定 + 超参数写进 config 说明 |
| N2 | 可读性 | 代码 docstring 中文/英文均可，CLI 说明中文（对齐根目录 docs/03） |
| N3 | 轻依赖 | 优先 sklearn/numpy/PIL/opencv-python，不引入大模型 |
| N4 | 文档驱动 | 每个方法在 report/ 有文献依据，在 docs/03 有设计定位 |

## 5. 验收标准

1. 3 个确定性基线 + 2 个高价值组合脚本可跑（冒烟 5 张 → 全量 300 张）
2. 评估 JSON 产出 → `_scores.json` 出现新模型行 → 雷达图/总分表更新
3. 复制检测通过（相似但不相同：复制率 ~0、NN 距离分布合理）
4. 报告 `report/05` 的章节结构有数据填充
5. 全过程用户审阅确认
