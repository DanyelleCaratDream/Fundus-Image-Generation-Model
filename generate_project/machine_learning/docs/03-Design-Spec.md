# 设计规范：传统 ML 生成管线架构（分层）

> 更新日期：2026-08-03 ｜ 核心思路来自 `report/04-synthesis-insights.md`（为什么分层）和 `report/02-literature-fundus.md`（各层文献依据）

---

## 1. 分层管线总览

传统 ML 生成眼底图的推荐架构分 **4 层**。每层可选多种实现，规模化时新方法只需替换/新增某层，不重写全套（满足需求 R6）。

```
结构层（骨架/布局）     纹理层（背景/病灶内容）     融合层（合成）          多样化层（最终润色）
├─ 现成分割器提血管/病灶  ├─ Image Quilting 拼布      ├─ Poisson 无缝融合      ├─ Retinex 光照交换
├─ ASM/Bonaldi 血管树合成 ├─ 稀疏字典学习（K-SVD）     ├─ patch 拼接 + min-cut  ├─ Reinhard 颜色迁移
├─ 过程化 CCO/DLA 血管生长 └─ Criminisi inpainting 抠背景└─ 泊松病变重排         └─ 直方图匹配
└─ PCA 潜空间结构插值（COCA）                                             └─ 记忆检测三件套质检
```

## 2. 各层职责

| 层 | 回答什么问题 | 输入 → 输出 | 典型实现 |
|:--|:--|:--|:--|
| **结构层** | 血管/视盘/病灶布局从哪来？ | 真实图/参数 → 结构 mask/骨架 | ASM 血管树、CCO/DLA 血管生长、分割器提 mask |
| **纹理层** | 背景/病灶内容从哪来？ | 真实图补丁 → 纹理库/新补丁 | Image Quilting、稀疏字典、inpainting 抠背景 |
| **融合层** | 结构 + 纹理怎么合成一张图？ | 骨架 + 纹理 → 合成图 | Poisson 编辑、patch 拼接 + min-cut 接缝 |
| **多样化层** | 怎么让"相似但不相同"且语义不变？ | 合成图 → 多样化的图 | Retinex 光照交换、Reinhard、直方图匹配 |

## 3. 方法映射到分层（当前计划）

| 方法 | 属于哪层 | 状态 |
|:--|:--|:--:|
| PCA 线性重建 | 结构层（潜空间）— 单层即可成图 | 🟡 确定性基线 |
| GMM 混合采样 | 纹理层（特征空间）— 单层即可成图 | 🟡 确定性基线 |
| 补丁拼接 | 纹理+融合层 | 🟡 确定性基线 |
| 泊松病变重排 | 融合层（病灶嵌入） | 🟢 高价值组合 |
| Retinex 光照交换 | 多样化层 | 🟢 高价值组合 |
| 血管骨架 + 纹理拼布 | 结构+纹理+融合 全管线 | ⚪ 可选（工程量高） |
| COCA 潜空间 | 结构层 | ⚪ 可选（科研向） |

## 4. 分层设计原则

1. **层间松耦合**：每层输入输出是标准接口（numpy array 或 mask），不互相依赖实现细节。
2. **可替换**：任何层换实现不影响其他层（例：结构层从"分割器提 mask"换成"ASM 生成"）。
3. **可组合**：一个完整方法 = 若干层串联；单层方法（如纯 PCA）也允许，作为基线。
4. **质量门控在末端**：多样化层之后统一跑"复制检测三件套"（见 §5），任何方法都过这道门。

## 5. 复制检测三件套（强制质检）

所有生成方法（不管哪几层）产出后必须通过：

| 检测 | 方法 | 阈值参考 | 用途 |
|:--|:--|:--|:--|
| 最近邻距离分布 | 每张生成图对 330 训练图算 SSIM/LPIPS 最近邻 | 分布合理（不塌缩到复制值） | 相似但不相同的直接验证 |
| 全图复制率 | 生成图 vs 训练图 L2/LPIPS 距离低于阈值的比例 | ~0 | 防整图复制（Feng 2021 方法） |
| 补丁重复率 | 生成图内 patch 自相似性 / 与训练图 patch 重复块占比 | 低 | 防局部复制（拼接法特有风险） |

实现：`scripts/memory_check.py`（待建，见 05-Execution-Plan 步骤 2.6）。

## 6. 扩展新方法的流程（规模化）

```
1. 查 report/ 文献依据 → 判断属于哪层
2. 按 docs/02 规范写 scripts/<method>_gen.py（CLI/输出对齐）
3. 若复用现有层组件 → import；否则新建该层实现
4. 冒烟 5 张 → 全量 300 张
5. 评估 + 复制检测三件套
6. eval_data JSON → score_scheme + plot_metrics 入图
7. 记录到 docs/06-Records + report/05 更新
```
